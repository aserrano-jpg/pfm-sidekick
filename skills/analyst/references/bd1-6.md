# Biz D1to6AI Reference

This dashboard tracks BD1to6AI. Atlassian's ML-adjusted quality signal for business-domain signups across all channels (organic + paid). Powers the Tableau dashboard at `go/fy26d16`.

Different from the paid reference:
- This reference: `production.marketing_insights.business_d1to6ai_tracking`. total channel view, scenarios, OKR pacing
- Paid reference: `marketing_paid_performance.paid_performance_campaigns`. paid-only, raw actuals + spend

---

## What BD1to6AI means

A signup qualifies as BD1to6AI when:
- It's a business domain email (`domain_type = 'business'`)
- The metric type is `metric = 'D1to6AI'`
- The user engages with the product within 6 days

BD1to6AI correlates strongly with purchase and seat expansion. It's the primary KR proxy for self-serve quality.

BD1to6AI ≠ `business_domain_d1to6` from the paid pipeline. This dashboard uses the ML-adjusted AI signal. The paid reference uses the raw D1to6 column.

## Column structure: primary table

| Column | Type | Description |
|---|---|---|
| `date` | Date | Snapshot date |
| `base_product` | String | Atlassian product name |
| `expand_type_tier2` | String | Grouped expand type (Land, Cross Flow, bundle, etc.) |
| `channel_group` | String | Grouped channel (organic, paid-search, paid-social, direct, etc.) |
| `base` | Numeric | BD1to6AI actuals. use for "what happened" |
| `target` | Numeric | Official KR target |
| `stretch` | Numeric | Aspirational target |
| `baseline` | Numeric | Conservative forecast |
| `is_valid` | Boolean | Always filter `= TRUE` to exclude pipeline artifacts |

> `domain_type`, `metric`, `scenario`, and `forecast_version` are handled by the dbt model. pre-filtered and pivoted. Do not add them as WHERE clauses.

**Scenarios are columns, not rows.** No `scenario` filter needed.

Attainment formula: `SUM(base) / NULLIF(SUM(target), 0)`

## Standard WHERE filters

```sql
-- Always include for primary table
WHERE base_product = '<product>'
  AND is_valid = TRUE
  AND date >= '<start>'
  AND date <= current_date() - interval 1 day
```

Do not add `domain_type` or `metric` filters. already applied by the dbt model.

## Common query patterns

### BD1to6AI actuals by product (monthly)
```sql
SELECT
  date_trunc('month', date)   AS month,
  base_product,
  SUM(base)                   AS bd1to6ai_actual,
  SUM(target)                 AS bd1to6ai_target
FROM production.marketing_insights.business_d1to6ai_tracking
WHERE is_valid = TRUE
  AND date >= '2025-08-01'
  AND date <= current_date() - interval 1 day
GROUP BY 1, 2
ORDER BY 1 DESC, 3 DESC
```

### Actuals vs. target attainment by product
```sql
SELECT
  base_product,
  SUM(base)                                       AS actuals,
  SUM(target)                                     AS target,
  SUM(base) / NULLIF(SUM(target), 0)              AS pct_attainment
FROM production.marketing_insights.business_d1to6ai_tracking
WHERE is_valid = TRUE
  AND date >= '2025-08-01'
  AND date <= current_date() - interval 1 day
GROUP BY 1
ORDER BY 2 DESC
```

### Channel group breakdown (paid vs. organic split)
```sql
SELECT
  date_trunc('month', date)   AS month,
  base_product,
  channel_group,
  SUM(base)                   AS actuals,
  SUM(target)                 AS target
FROM production.marketing_insights.business_d1to6ai_tracking
WHERE is_valid = TRUE
  AND date >= '2025-08-01'
  AND date <= current_date() - interval 1 day
GROUP BY 1, 2, 3
ORDER BY 1 DESC, 4 DESC
```

### Motion breakdown (Land vs. Cross Flow)
```sql
SELECT
  date_trunc('month', date)   AS month,
  base_product,
  expand_type_tier2           AS motion,
  channel_group,
  SUM(base)                   AS actuals,
  SUM(target)                 AS target
FROM production.marketing_insights.business_d1to6ai_tracking
WHERE is_valid = TRUE
  AND date >= '2025-08-01'
  AND date <= current_date() - interval 1 day
GROUP BY 1, 2, 3, 4
ORDER BY 1 DESC, 5 DESC
```

### YoY comparison
```sql
SELECT
  year,
  month,
  base_product,
  expand_type_tier2,
  channel_group,
  SUM(base)     AS current_year_bd1to6ai,
  SUM(base_ly)  AS prior_year_bd1to6ai,
  SUM(base) / NULLIF(SUM(base_ly), 0) - 1 AS yoy_growth
FROM production.marketing_insights.business_d1to6ai_tracking_yoy
WHERE is_valid = TRUE
GROUP BY 1, 2, 3, 4, 5
ORDER BY 1 DESC, 2 DESC, 6 DESC
```

## Diagnostic framework

When BD1to6AI moves WoW or MoM:

1. **Product**. which `base_product` drove it?
2. **Channel group**. paid vs. organic? (`channel_group`)
3. **Expand type**. land vs. cross-flow vs. bundle? (`expand_type_tier2`)
4. **Lag**. BD1to6AI has a ~7-day bake lag. Recent dates will be understated.
5. **is_valid flag**. confirm `is_valid = TRUE` filter is applied in both tables.

---

## Gotchas

| Gotcha | Rule |
|---|---|
| Not paid-only | `channel_group` includes organic, direct, product-surface. don't equate to paid performance |
| Scenarios are columns, not rows | Use `base` for actuals, `target` for KR target. no `scenario` row filter needed |
| `domain_type` / `metric` are pre-filtered | The dbt model already filters to business domain D1to6AI. don't add those WHERE clauses |
| BD1to6AI ≠ `business_domain_d1to6` | This uses the ML-adjusted AI signal; paid reference uses raw D1to6 column |
| 7-day bake lag | Recent week's data will be understated. always flag this |
| `is_valid` filter required | Always filter `is_valid = TRUE` in both tables to exclude pipeline artifacts |

## Channel group values

The raw `channel` field is grouped into `channel_group`. Common groups:
- `paid-search`. BPS + NBPS
- `paid-social`. Reddit, LinkedIn, etc.
- `organic`. SEO / unpaid search
- `direct`. direct navigation
- `cross-flow` / product-surface. Nav4, MFY, etc.

To see current values:
```sql
SELECT DISTINCT channel_group
FROM production.marketing_insights.business_d1to6ai_tracking
LIMIT 50
```
